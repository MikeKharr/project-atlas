# project-atlas

[English version](README.md)

project-atlas читает репозиторий по явному списку путей и строит граф его
документов, правил, агентов и единиц деплоя: ADR, записи истории,
спецификации дизайна, гайды, инварианты, роли агентов и ярусы моделей,
скиллы, классы гейтов и фазы цикла из ручного overlay, нумерованные единицы
приложений, сервисы Compose, тома и внешние сервисы. Рёбра — цитаты, замены,
опоры на инварианты, упоминания ролей, маршруты, зависимости, тома, вызовы и
следы гейтов в записях истории.

Сборка пишет:

- `graph.json` и `texts.json` для статической витрины (`web/`);
- производный vault Obsidian, где цитаты заменены на `[[wikilinks]]`;
- и больше ничего — исходный репозиторий не меняется никогда.

Node 22, без зависимостей.

## Запуск

```sh
node build.js --root test/fixtures/minimal --check                  # только проверка, ничего не пишет
node build.js --root test/fixtures/minimal --out temp/minimal       # граф, витрина и vault
node build.js --root test/fixtures/minimal --out temp/minimal --serve   # то же и витрина на 127.0.0.1:8080
node --test test/*.test.js
```

| Параметр | По умолчанию | Смысл |
|---|---|---|
| `--root` | текущий каталог | какой репозиторий читать |
| `--config` | `<root>/atlas.config.json` | конфигурация проекта |
| `--out` | `<пакет>/dist` | каталог выхода |
| `--check` | выключен | только проверка: ничего не пишется, код 1 при любой находке |
| `--serve` | выключен | после сборки отдать `<out>/site` на `127.0.0.1:8080` |

Коды выхода: `0` — находок нет; `1` — находки (печатаются как
`файл:строка: сообщение`, в Actions — аннотациями; ничего не записано);
`2` — сборка не может начаться (нет конфигурации или она не JSON, неверные
аргументы, опасный каталог выхода).

## Конфигурация

Всё, что относится к проекту, — в двух файлах целевого репозитория:

- `atlas.config.json` — какие пути читать и как проект называет коллекции
  документов, единицы и части деплоя;
- ручной overlay (путь к нему — в конфигурации): классы гейтов, фазы цикла,
  внешние сервисы и факты, которых нет ни в одном машинно-читаемом файле.

Контракт обоих файлов и выходов — [`docs/input-spec.md`](docs/input-spec.md)
(формат 1, на английском). Два полных примера:

- [`test/fixtures/minimal/`](test/fixtures/minimal/) — синтетический проект
  без дизайна, гайдов, скиллов, единиц и деплоя;
- [`examples/ai-advent-2026/atlas.config.json`](examples/ai-advent-2026/atlas.config.json)
  — проект, из которого инструмент выделен; см.
  [его README](examples/ai-advent-2026/README.md).

Соглашения документов (имена разделов, слова статуса, признаки гейтов) —
словарь `lib/vocab/ru.js`. В формате 1 — только русский; интерфейс витрины,
тексты заметок vault и сообщения находок тоже русские.

## Границы

- **Читается только названное.** Каталоги перечисляются нерекурсивно, по
  маске файлов. Каждое чтение и перечисление проходит один страж: путь лежит
  под входом из конфигурации, не попадает под запретный список (`.env*`,
  `*.env`, `temp/`, `logs/`, `data/` на любой глубине, `*.sqlite*`, `*.log`,
  `node_modules/`, `.git/`), на пути от корня нет символических ссылок, а
  настоящий путь лежит под настоящим корнем. Нарушение — находка, файл не
  читается. Каталог единиц только перечисляется: код приложений не читается.
- **Пишется только каталог выхода.** `<out>` разворачивается в настоящий путь;
  он не корень и не его предок и не пересекается ни с одним входом. Ничто из
  удаляемого и записываемого не может быть символической ссылкой, а настоящий
  каталог каждого записанного файла лежит под настоящим `<out>` — поэтому
  `<out>` внутри корня (`dist/`) разрешён: подложенная метка не выведет запись
  за его пределы. Сборка
  удаляет `<out>/site/` и свои каталоги vault — только если `<out>` новый,
  пустой или несёт метку `.project-atlas` прошлой сборки; иначе отказ, ничего
  не удалено. `.obsidian/` внутри vault не трогается. `--check` каталог выхода
  не разрешает и не проверяет.
- **Происхождение** (коммит, его дата, признак правок) берётся из git, только
  если корень — вершина рабочего дерева git. Иначе полей нет, и vault говорит,
  что коммит неизвестен.

## Выходы

### `graph.json`

`{ provenance: { sha, dirty, date }, nodes, edges }` с отступом в два
пробела. Порядок узлов и рёбер задан спецификацией: от него зависит раскладка.

- `x`, `y` у каждого узла — единичный квадрат `0…1`, шесть знаков,
  детерминированная силовая раскладка с фиксированным семенем.
- `z` у каждого узла — глубина для объёмного вида, `0…1`, считается после `x`,
  `y` и их не меняет; узлы без рёбер — `0.5`. В объекте стоит перед `x`.
- `marks` у рёбер `fired` — `{ unit, role, sign }`, полуинтервалы в единицах
  UTF-16 по `excerpt` до обработки разметки.
- Выдержка следа не обрезается: целая фраза или строка таблицы.

### `texts.json`

Один объект `{ "<id узла>": "<текст>" }` в порядке узлов, без отступов, с
переводом строки в конце — для полнотекстового поиска витрины. Документы,
роли и свои скиллы; фронтматтер, решётки заголовков, выделение, обратные
кавычки и разметка таблиц сняты.

Секреты — последним шагом:

- **Образец ключа с хвостом** (префикс ключа Anthropic или Groq с хвостом
  длины ключа, заголовок приватного ключа PEM, токены GitHub с хвостом) в
  любом прочитанном документе — находка: ничего не пишется, сообщение называет
  образец и строку, но не найденное. Тот же список (`KEY_SAMPLES` в
  `lib/texts.js`) ищет по всему дереву задача CI `secrets`.
- **Законно упомянутые образцы** (голые префиксы ключей, заголовок ключа
  OpenSSH, адреса CGNAT) заменяются в `texts.json` на `[скрыто]`.

### Витрина

`web/` — `index.html`, `app.js`, `style.css`: без зависимостей, только API
браузера, относительные пути. Сборка кладёт в страницу имя проекта, адрес
репозитория и необязательный документ «как устроен этот атлас» тегами
`<meta name="atlas-…">`; в `app.js` констант проекта нет. Ссылки на файлы
прибиты к коммиту сборки.

### Vault

Фронтматтер, блок происхождения (путь источника, коммит, время коммита,
пометка «только для чтения») и текст документа с цитатами-ссылками
`[[wikilinks]]`. Пересборка неизменного репозитория даёт побайтово те же
заметки: время — время коммита, а не «сейчас».

### Потолки размера

`texts.json` — 3072 КБ, `graph.json` — 1024 КБ, код страницы — 256 КБ (`LIMITS`
в `build.js`). Превышение — находка; усечения нет.

## Код

```text
build.js         CLI: --root, --config, --out, --check, --serve; граница записи
lib/config.js    чтение и проверка atlas.config.json, разрешённый список входов
lib/sources.js   чтение входов через страж; ссылки и запретный список — находки
lib/markdown.js  фронтматтер, разделы, грамматика цитат из конфигурации
lib/compose.js   узкий парсер подмножества Compose; непонятая строка — находка
lib/fired.js     следы гейтов: имя роли рядом с признаком в записи истории
lib/layout.js    детерминированная силовая раскладка: x, y и z каждого узла
lib/extract.js   узлы, рёбра и находки
lib/texts.js     texts.json и образцы секретов
lib/vault.js     заметки Obsidian
lib/vocab/ru.js  словарь соглашений документов
```

## Совместимость (формат 1)

Формат 1 определён так: на `MikeKharr/ai-advent-2026` при
`1d882f40f8c37370b4dfbc3add650f10d1b11c1c` с конфигурацией примера инструмент
даёт `graph.json` и `texts.json`, побайтово равные `node atlas/build.js` в том
же checkout. Это проверяет `test/compat.test.js` — и то, что `site/` и
`vault/` отличаются только четырьмя названными файлами:

| Файл | Отличие |
|---|---|
| `site/index.html` | теги `<meta name="atlas-…">` |
| `site/app.js` | нет констант проекта; общая формулировка подвала |
| `vault/index.md` | `ИСТОЧНИК: build.js` вместо `atlas/build.js` |
| `vault/skills/skill-inspector.md` | набор вендорного скилла берётся из lock-файла скиллов |

Без `ATLAS_REFERENCE_ROOT` — пути к чистому checkout этого коммита — тест
пропускается; задача CI `compat` такой checkout создаёт. Обе сборки должны
идти в одном часовом поясе: время коммита форматируется в местном.
